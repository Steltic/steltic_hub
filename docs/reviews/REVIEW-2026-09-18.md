## Fixed

| # | Severity | Where | What was wrong | Fix |
|---|---|---|---|---|
| 1 | **High** | `main.py` | The hub binds to loopback with no authentication and no origin check. A browser sends a "simple" cross-site request (a POST with no body, or a `text/plain` body) with **no CORS preflight** — CORS only hides the reply. So a page on any site the user had open could `POST /api/connection` with `text/plain` JSON (the hub parses it regardless of content type) and redirect the LLM key to its own endpoint; `POST /api/modules/custom` with a manifest naming its own git URL, then `POST /api/modules/<id>/install` — `git clone` + `uv pip install -e .` runs the repo's build hooks; start runs; delete projects. Confirmed with a TestClient: all four went through. | A middleware refuses any non-GET request whose `Origin` (or `Sec-Fetch-Site: cross-site`) is not a loopback origin, and any request whose `Host` is not a loopback name (DNS rebinding). Same-origin pages, the Edge `--app` window, the Tauri webview, the launcher's `Invoke-RestMethod`, `curl` and module servers send no `Origin` or a loopback one and are unaffected. |
| 2 | Medium | `envs.py` | `invalidate()` cleared the interpreter check but not `_OPTIONAL_CACHE`. After **Rebuild env** (or Remove + Install) the interpreter is new and Docling is gone, but the cached `present: true` survived, so the Convert tab's gate — built precisely to refuse a run before the ImportError — stayed open and the run died on the first import. Reproduced. | `invalidate()` drops both caches (per module, or all). |
| 3 | Low | `manifest.py` | `run.retry.then_set` is applied from the **third** attempt (`run_cli`), so a manifest with `then_set` and `max: 2` is read, accepted and never applies — the kind of silent no-op the retry validator was written to refuse. | Refused with a message; the shipped manifest (`max: 3`) is unaffected. |
| 4 | Low | `tauri/src-tauri/src/main.rs` | On window close the shell called `kill()` on the hub — `TerminateProcess`, so the hub's shutdown hook never ran and every module server (and the OpenSees run inside it) was orphaned, the opposite of what the comment said. | `POST /api/hub/shutdown` first, wait up to 20 s for the hub to exit, kill only what is left. **Not compiled here** (no Tauri toolchain in the review environment); the change is a `ureq::post` call in the same style as the existing `wait_healthy`. |
| 5 | — | `README.md` | Clone URL said `steltic-hub`; every sibling repo is underscored (`steltic_cfs`, `steltic_grokbot`, …) and the folder and package are `steltic_hub`. | `Steltic/steltic_hub`. |

## Added

* **`{hub_url}` template** (`config.hub_url()`, `runners.base_ctx`): the URL the hub actually bound
  (from `hub.url`), so a module server can drive other modules through the hub's own API without the
  hub knowing anything about that module. Generic; documented in the README's template list.
* **Admin module** — `catalog/steltic_admin/` (bundled, like Design variations): batch plans across
  projects and modules through `/api/run`, run monitoring with per-step logs, the standards
  conversion queue, and a help desk over the code and docs. Its own README explains it; 15 tests.
  Verified end to end on a live hub: installed through the hub, started by the hub with `{hub_url}`,
  and ran a three-step plan against a linked stdlib module — the hub's `hub_runs.jsonl` agreed with
  Admin's record step for step.
* `.gitignore`: `patches/`, `Claude outputs/`, `.pytest_cache/`, `*.zip`, `*.bundle`, `.venv/`.
  `patches/` holds 9.5 MB `.patch` files that belong to the *module* repos (they are what the git
  agent applied there), and `Claude outputs/` is round-by-round hand-off material; neither is hub
  source. Delete the lines if you want them tracked.

## Noted, not changed

These are design limits rather than defects; they matter for how Admin is used and for what to do
next, so they are recorded here.

* **A run dies with its client.** `run_cli` / `run_http` are the SSE response: when the browser
  drops the connection (a reload, Ctrl+Shift+R, the Edge window closing) the generator is cancelled
  and its `finally` terminates the process tree. `beforeunload` warns, but a 90-minute NLRHA still
  ends with the window. Admin holds each run's stream open in its own process for exactly this
  reason, so a batch survives the window — but **Restart hub** stops every module server, Admin
  included. The structural fix is a hub-side run registry (detached runs with a log buffer and a
  re-attachable stream); about a day, and it would also let the window reconnect after a reload.
* **`stage_inputs` copying a folder into one of its own descendants** would recurse (the
  `from`-inside-`to` case is skipped; the reverse is not). No manifest does this; a guard is one
  line if a future one might.
* **`ServerSupervisor._wait_healthy`** leaves `ports[mod_id]` / `deps[mod_id]` behind when a server
  exits immediately; harmless (the next start reallocates), just untidy.
* **`ui/app.js` loads pdf.js from cdnjs** for the attachments field's PDF text extraction — the one
  thing in the hub that needs the internet; it fails gracefully offline.
* **`fileField` (multi-file) splits a string value on `[;:]`**, which would split a Windows drive
  letter; values there are normally arrays, so it does not bite.
* **pyflakes**: unused imports in `probabilistic/worker.py`, `variations/main.py`,
  `variations/prompts.py`, `variations/steltic_client.py`, and an unused local in
  `tests/test_variations.py:342`. Cosmetic.
* **Tauri `free_port()`** picks a port, releases it, then starts the hub on it; if the hub loses the
  race it falls back to another port and writes `hub.url`, which the shell does not read. Only the
  optional shell; the launcher handles it correctly.
* **Windows path in a Linux-style env var**: `steltic_grokbot.json` sets
  `TESSDATA_PREFIX=/usr/share/tesseract-ocr/5/tessdata/` on every platform. Harmless on Windows
  (Docling ignores a missing folder) but worth a `{module_dir}`-relative value if Tesseract is ever
  used there.
