# openBIM drawings in the existing question flow

Update the User-designed building module to install its pinned openBIM dependency. **Questions** links to the drawing information requests, and **Drawings / info** opens them directly. The catalog also offers an independent openBIM module. Both use the same widget and project revision store.

**Request register / answer queries** opens the editable register and expands the first unresolved request. The separate **Download request data (JSON)** link exports data. To receive this fix, update openBIM, stop and relaunch that module, then refresh its drawing tab; update User-designed building as well if using its embedded drawing page. Existing answers and revisions are retained. The 0.6.1 fix passed twelve drawing-workflow checks, four Hub integration checks and a browser form-save check using an isolated HR fixture.

Choose a completed HR/CFS job containing a physical `bim_package.json`, or upload that export. Drawing information requests have explicit proposals accepted for provisional drawing by default. They do not block PDFs. Proposed positions/sizes remain dashed and labelled `TBD - resolve query`, with their dimensions omitted.

Users can add information, quantitatively confirm an opening layout, reopen it, regenerate the set or import a revised physical package. Confirmed opening coordinates update the overlay and its schedule; prior PDFs/answers remain in revision history. Engineering/supplier notes require an updated source package to change structural geometry. No text answer silently cuts/redesigns framing or confirms an unresolved dimension.

Existing required HR build inputs, model checks and nonlinear confirmation gates retain their behavior. The shared drawing API uses the existing local request guard, source/revision checks, file locks and atomic publication. `OPENBIM_JOBS` is the shared openBIM module jobs path; `HR_JOBS` and `CFS_JOBS` are source export roots.

The drawing module includes **43 registered fictional review buildings**: three original pilots, twenty additional HR and twenty additional CFS cases. For an exact registered source package, the existing query widget offers explicit fictional-building confirmation, then generates dimensioned A1 plans, sections, member marks and assembled connection details. Each joint has elevation, cut section, isometric, parts, attachments and dimensions. Source values are marked S; adopted fit, missing positions and delegated geometry are marked A. These are design review sets, without new capacity checks or fabrication approval. Ordinary jobs keep the provisional workflow and cannot acquire fictional review answers. See [the 43-building review and reproduction record](https://github.com/Steltic/steltic_openBIM/blob/main/docs/stage7/README.md).

Update both openBIM and User-designed building in the Hub to pick up this catalog and the pinned drawing dependency. The shared store retains answer and PDF revisions. General automatic detailing for unregistered buildings and IFC export remain subsequent work.

The current drawing integration tests cover provisional publication, shared project storage, fictional adoption for both review batches, assembled JSON/PDF downloads, stale-revision rejection, reopening questions and the existing model-check gate.

For this catalog expansion, all four drawing integration tests passed with the 0.6.0 renderer, including a portal case from the second batch. The earlier interface work passed 30 focused Hub checks, including the real API import/answer/PDF loop and preserved model gates, and was browser-tested on the actual User-designed building page. Earlier broader checks exposed three failures also reproduced on unchanged main (two Windows crash-code fixtures and a path-error wording assertion), plus timing-dependent behavior in the unchanged legacy staging test. Those unrelated runner areas are not modified here.
